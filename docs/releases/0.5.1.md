# proxy-agent 0.5.1 — SSH Jump + Identity + Path Health

## Release status

- Version: `0.5.1`
- Release baseline: commit `361f28eeef3925acd37e085ff3384a45c2a8fac8` (PR #43 merge)
- Release type: single-hop SSH transport expansion
- Web/LAN management is not part of this release.

## Highlights

0.5.1 makes the frozen Egress Path contract operational for one-hop SSH:

`Local -> Jump -> Target`

The implementation reuses the existing `ssh-socks` lifecycle, ownership, PID/listener checks, runtime state, health/reconcile state, and Control API boundaries rather than introducing a parallel lifecycle subsystem.

### Jump path

- One-hop SSH Jump Host support is implemented.
- Deeper multi-hop chains are rejected.
- Jump and Target failures are distinguishable in validation and path health.
- An unreachable Jump does not get collapsed into a false Target failure.

### Identity and host keys

- Jump and Target use independent identity references.
- File-backed identity and `known_hosts` references are resolved through the existing reference layer.
- Strict host-key verification remains the default.
- Private-key material is not exposed through API responses, revisions, audit records, or diagnostics.

### DNS and path health

- `dns_mode: remote` preserves the established `socks5h` behavior.
- `dns_mode: local` is explicit and diagnosable.
- Path health records transport, Jump, Target, proxy, overall state, causal reason, and last-check timestamp.
- Status queries remain side-effect free; network probes belong to the health runner and cached observations are injected into runtime state.

### Recovery and compatibility

- Recovery remains bounded and observable.
- Existing direct `ssh-socks` profiles remain supported.
- Existing lifecycle and process ownership semantics are retained.

## Acceptance / release evidence

PR #43 was merged only after the repository's CI, Path Health smoke, Functional smoke, ShellCheck, and Upgrade Transaction Gate passed.

The complete 0.5.0 regression gate remains part of the 0.5.1 release exit condition, together with direct-path regression and one-hop Jump-path acceptance.

## Explicit non-goals

- Web or LAN management.
- More than one Jump hop.
- Multi-hop configuration DSL.
- Automatic failover or load balancing.
- Multiple Egress Path selection.
- Universal connection draining / zero-downtime activation.
- Full RBAC/SSO.
- External secret-provider framework.
