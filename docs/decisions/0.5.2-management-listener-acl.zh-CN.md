# 0.5.2 管理监听与 LAN ACL 决策

状态：已实现，作为 0.5.2 Web/LAN Management Plane 的部署边界决策。

## 裁决

管理监听属于 Runtime + Deployment / User Surface 边界，而不是 profile revision 的业务配置。当前 systemd 单元已经通过 `PA_WEB_LISTEN`、`PA_WEB_PORT`、TLS 环境变量和 `web-admin-token` 驱动 `proxy-agent-web-ui`，因此本阶段继续沿用该部署输入链，不新增一套 management state store。Revision、Audit、Desired/Observed 与 Reconcile 仍由现有 Control API/runtime 链拥有。

默认监听继续为 `127.0.0.1:8443`。回环监听不要求 ACL，因为 TCP bind 本身已经把可达面限制在本机。

非回环监听必须同时满足：

1. TLS certificate + private key；
2. 至少一个显式允许的 CIDR。

ACL 输入来自 `--allow-cidr`，或 systemd 部署环境中的 `PA_WEB_ALLOW_CIDRS`。可重复指定，也可使用逗号分隔；解析采用 Python `ipaddress`，支持 IPv4/IPv6，并以实际 TCP peer address 判断，不信任 `X-Forwarded-For` 等代理头。

ACL 检查发生在 Web UI handler 进入静态页面、healthz、session 与 Control API 代理逻辑之前，因此认证与 CSRF 不会成为网络边界的替代品。

## 数据/调用链

```text
systemd
  -> PA_WEB_LISTEN / PA_WEB_PORT / PA_WEB_ALLOW_CIDRS / TLS env
  -> bin/proxy-agent-web-ui
  -> WebUIHandler._require_network()
  -> existing session + CSRF + auth audit logic
  -> UnixHTTPClient
  -> /run/proxy-agent/control.sock
  -> proxy-agent-api-auth
  -> existing revision/audit/reconcile ownership
```

## 兼容性

没有改变现有 loopback 默认部署，也没有改变现有 token/session/CSRF、Control API v1 或 revision 乐观并发语义。现有 `web.env` 仍是可选文件；新增变量为空时，loopback 默认行为不变。

## 已知边界

ACL 拒绝本身不会写入 `auth-events` 审计事件，因为该接口当前只接受 login/logout 四类认证事件；这避免在认证事件接口之外引入平行审计协议。本阶段保持该边界，后续若需要安全访问日志，应扩展正式 Audit Contract，而不是在 Web 层直接写 audit 文件。
